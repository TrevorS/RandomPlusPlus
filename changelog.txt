2026/7/29 - v1.0.0 (first release as RandomPlusPlus)
-Version numbering restarts at 1.0.0. The original tracked the RimWorld version it
 was built for, which stops working now that one build serves both 1.6 and 1.5.
 This number is the mod's own; supportedVersions in About.xml says which games it
 runs on.
-Rebuilt against Harmony 2.4.1, matching the version the Harmony mod loads at runtime (was 2.0.0.6)
-The project now builds without a RimWorld installation, using published reference assemblies
-Corrected assembly metadata, which still identified the mod as "ClassLibrary1",
 and it now names this fork rather than the original author
-Fixed the fast reroll algorithm never satisfying a gender filter. Gender is not
 regenerated by a fast reroll, so a pawn that started on the wrong gender could
 never match, and the reroll limit was spent before handing back that same pawn.
-Fixed the fast reroll algorithm generating apparel and weapons from the previous
 candidate's age and stats. Gear is now rolled once a pawn has passed the filters,
 which also skips a full apparel and weapon roll for every rejected candidate.
-Fixed the "count only highest attack skill" option reading the wrong two skills
 when another mod adds a skill that sorts before shooting. Shooting and melee are
 now identified by definition rather than by position in the skill list.
-Fixed the trait pool size being checked against every filtered trait instead of
 only the optional ones. A pool larger than the optional set could never be
 satisfied, so the filter silently used up the whole reroll limit on every
 randomize and returned a pawn that ignored it.
-Removed the reroll algorithm setting. There is now a single search, which
 regenerates only the parts of a pawn the filter reads and abandons a candidate as
 soon as one of them fails. Where regenerating in place is unsafe (Humanoid Alien
 Races, the choose-wanderers dialog) the same search rerolls whole pawns instead.
-Generation steps are now called through bound delegates rather than reflection, and
 the filter checks no longer allocate, so a search no longer creates garbage per
 candidate.
-Work priorities are built once for the pawn that is kept, rather than for every
 rejected candidate.
-Compatibility with other mods is now detected rather than hard-coded. The search
 asks Harmony whether anything else has patched pawn generation, instead of looking
 for one mod by name, so it no longer takes the slow path for mods that are
 harmless and no longer takes the fast one for mods that would break.
-Candidate pawns no longer have apparel, weapons or inventory generated, since no
 filter reads them. The chosen pawn gets its gear before it is handed back, and the
 whole thing is disabled if another mod has patched gear generation.
-A failure to read the saved filter file no longer deletes it. It is moved aside as
 .corrupt instead, so the filters are still there to recover.
-Trait filtering is now correctly skipped for Well Met users even when the filter
 editor was never opened, such as when a filter is loaded from disk.
-Removed a developer-mode shortcut that restarted the game when the up arrow was
 pressed with the filter window open.
-The build now runs every .NET analyser rule as an error, with the rules that do not
 suit a RimWorld mod switched off individually and with a reason. This turned up two
 unused fields, five needless list enumerations and a trait sort whose order depended
 on the player's locale by accident rather than by choice.
-Source formatting is now consistent across the whole tree and checked by CI. The
 pass was whitespace only, and the compiled code was verified unchanged: all 334
 method bodies were byte-identical before and after.
-Removed 22 texture files the mod never used. They were being loaded into memory at
 startup along with everything else, and shipped in the download.
-Removed a further 47 unused members from the forked UI code: colours, rect helpers,
 an interface with one implementer and no callers, and several properties nothing
 read.
-Reorganised the source into Core, Game and UI. The filter and search logic is now
 separated from everything that needs RimWorld's UI, which is what the tests already
 relied on informally.
-Renamed the RandomSettings class to PawnRandomizer. It has not been a settings class
 for a long time; it runs the reroll search.
-Published as a fork, named RandomPlusPlus. New packageId (trevors.randomplusplus),
 so it no longer collides with the original mod, and declared incompatible with it
 since both replace the same randomize button. Removed the Steam item id, which
 pointed at the original author's Workshop upload.
-The download now extracts to a RandomPlusPlus folder rather than RandomPlus, so
 installing it cannot overwrite an existing copy of the original mod.
-Fixed the Reset All and Save/Load buttons in the filter editor being drawn in the
 middle of the window at any UI scale other than 1. Their positions were divided by
 the UI scale, but window contents are already drawn in scaled units.
-Log messages are prefixed with the mod's name, so a log can be read without
 guessing which of the two mods wrote a line.
-Health generation failures inside the reroll loop no longer write up to a hundred
 log lines per candidate. They are reported once, after the retries are exhausted.
-A filter naming a skill the pawn does not have (a modded pawn kind, or a mod that
 removed a SkillDef) no longer writes one error per candidate. It reports once,
 names the skill, and ignores that part of the filter rather than rejecting every
 pawn.
-Supports 1.6 and 1.5, both built from this source, so every fix above applies to
 both. Previously only the 1.6 assembly was this fork's; 1.5 shipped the original
 mod's build with none of the fixes in it.
-Dropped 1.2, 1.3 and 1.4. Their assemblies were the original mod's from 2021-2024
 and this source cannot be compiled for them - the reroll search is built on
 generation entry points those versions do not have. Use the original mod there.
-The mod list preview image is now named About/Preview.png, which is the name
 RimWorld looks for. The lowercase name it had showed no preview on Linux.
-Added a mod icon: two dice, each showing a five-pip plus. Source is
 assets/ModIcon.svg, rendered by Tools/render-icon.py.
-Added a Makefile. make build, make install, make check; make on its own lists
 the targets. make install copies the mod straight into RimWorld's Mods folder,
 finding Steam and GOG installs on macOS and Linux.
-CI builds on macOS as well as Linux, and re-runs the scripts under /bin/bash so
 the bash 3.2 that macOS ships is covered rather than assumed.
-The mod is named RandomPlusPlus everywhere. The mod list was showing a separate
 short name, RandomPlus++, which read as a third spelling.
-The assembly is RandomPlusPlus.dll now, matching the mod's name. RimWorld loads
 assemblies by folder, not by name, and saved presets resolve types by namespace,
 which is unchanged - so nothing a player has breaks. Renamed before the first
 release deliberately: renaming after one would let an upgrade-by-overwrite leave
 both dlls in place, loaded twice.
-While a search runs, the pawn's card shows a search panel - the live reroll
 count and a rolling sample of candidate names - instead of the pawn itself.
 Mid-search the pawn is always part-way through a reroll, so drawing it live
 flickered through half-generated composites at whatever speed candidates
 failed. Skipping its portrait during the search also costs less.
-The game no longer freezes while a search runs. The search used to run to
 completion inside the Randomize click, which for a large reroll limit meant
 seconds of frozen window - a beachball on macOS. It now runs in time slices,
 one per frame: the game keeps drawing, the reroll counter counts up live, and
 clicking Randomize again during a search does nothing rather than queueing.
 Closing the page mid-search stops the search and leaves that pawn finished.
 The candidates are generated on the same thread in the same order as before,
 so this changes when the work happens, never which pawns come out.
